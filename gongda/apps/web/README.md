# 工单协作平台前端

React + TypeScript + Vite，普通CSS，中文企业管理界面。当前为第2步：真实主数据与版本管理，以及明确不落账的业务规则预检。页面不复用参考系统商标，不内置登录凭据，不自动创建业务样例。

## 启动与检查

依赖由根工作区统一安装。在仓库根目录运行：

```sh
npm run dev:api
npm run dev:web
npm run typecheck -w @gongdan/web
npm run build -w @gongdan/web
```

前端绑定 `127.0.0.1:5173`，`/api`代理到 `127.0.0.1:3001`。访问 `http://127.0.0.1:5173`。生产部署应使用同源网关提供前端和API，另行完成HTTPS、安全cookie及发布验证。

## 真实管理页面

- 登录、`/auth/me`会话恢复、企业上下文、退出；HttpOnly cookie交由浏览器管理，CSRF仅保存在React内存，不放入localStorage/sessionStorage。
- 概览读取真实产品、单位和审计计数；单位总数含停用档案，员工无审计计数权限时明确显示权限限制。
- 产品查询、服务端搜索与分页、创建、修改和乐观版本冲突提示；保留第1步真实接口。
- 单位创建及修改名称/启用状态，保存带并发版本。
- 工序创建及修改标准分钟、说明、报工授权人员、启用状态；至少授权一人。
- 工艺路线：工序顺序上移/下移、增加/移除、逐工序自动入库配置；查看当前和历史修订，修改保存为不可变新版本。
- BOM：母件、组件、精确字符串用量/损耗率、冻结投料路线版本、路线内投料工序与自动扣料配置；查看历史并保存新修订，追加版本不修改父件主档。
- 子BOM展开区分三种语义：省略子版本由服务自动冻结最新子BOM；显式null作为叶子不展开；具体版本ID冻结选中的历史版本。界面对应三种选项。
- BOM需求预览调用真实展开接口，按所选冻结版本和数量返回需求、路径及警告；不占用库存、不转采购/生产、不形成交易台账。用量1.03按1.03计算，不解释成损耗。
- 审计：管理员/计划员查看服务返回的事件、操作者、时间和前后值；员工不请求审计接口。

主数据写入仅提供给admin/planner，所有写请求带内存CSRF；worker只读。产品与其他写入不接受用户提供的tenant_id，企业边界由会话及服务端执行。

### 当前目录范围

工序、路线、BOM的列表本轮最多返回200条，界面显示实际返回数、服务总数及limit；超过上限时明确提示当前并非全量，分页在后续补齐。单位在服务未给出total时只称本次返回数。

BOM产品选择调用已有产品分页接口，`page_size=100`，显示匹配总数；超限要求按编号/名称搜索缩小范围，不把首100条当成完整产品目录。原版本已选对象保留显示，防止过滤后丢失当前关联。

## 不落账预检页面

“业务流程原型 · 预检”和“手机报工原型 · 预检”使用 `/design-preview/definitions` 动态生成模型、状态、动作与事实字段，再调用 `/design-preview/transition`。

- 定义包括sales、work_order、report、stock_movement；事实布尔/数量/整数/枚举均从服务定义生成。
- 结果明确展示允许/拒绝、下一模型状态、拒绝原因、拟产生效果，以及`posted:false`、暂定规则。
- “仅采用模型状态继续预检”只改变当前页面的模型状态。
- 手机页仅选择report模型，可以输入良品0、不良10进行全不良预检，不显示“已报工”或其他交易成功提示。
- 没有真实扫码、手机离线提交、销售单、生产工单、报工记录或库存台账的保存功能。

路线/BOM不可变版本及相关冻结规则是本平台为历史稳定性采用的设计；参考系统版本规则仍未完成取证，不将此设计冒称原系统已验证规则。
