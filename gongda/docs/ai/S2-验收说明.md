# S2 聊天一扔就落单 · 验收说明

> 基线：`release/sedric-v1.0.23`（`22e80ae…`）毛玻璃侧栏 + chat-shell  
> 叠层：S0 `ai-s0-trust-base` + S1 `ai-s1-factory-ask`  
> 本功能版本：**SEDRIC01 v1.0.26** · feature `ai-s2-chat-intake`  
> 规格：`AI四能力-交互规格-2026-10-20.md`

## 范围

主入口：**聊天框扔附件**。写库一律：**认型 → 预览确认卡 → `POST /api/ai/writes/confirm` → `ai_action_audit`**。

| 认型 | 动作 |
|------|------|
| `order_doc` | 合同预览确认卡；确认后写 `money_contracts`(+明细)；**串加工单默认关**，若开启须二次确认预览 |
| `business_card` | 联系人预览；确认后写 `money_contacts`（可新建客户）；原图挂 `attachments`；**禁止**合同/加工单 |
| `other` | 追问：存附件 / 忽略 / 强制当单据；禁止静默落单 |
| `unknown` | 追问 + 选项；禁止静默落单 |

## Mock 边界（务必知晓）

- **无 OCR**：认型与字段抽取依赖文件名 + 文本内容的确定性规则（`classifyAttachmentHints` / `parseOrderDocFields`）。
- 冒烟可用 `.txt` fixture 模拟名片/送货单；协议与写库路径是**真实**的（同一 `preview_id`、统一 writes、审计表）。
- 商品须在企业内已存在（或可匹配）；演示库常用 `LOCAL001`。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/ai/intake/classify` | 认型；名片/订单出 `confirm_card`+`preview_id`；other/unknown 出 `ask`+`ask_id` |
| POST | `/api/ai/intake/resolve` | 追问决议（ignore / keep_attachment→确认卡 / force_*） |
| POST | `/api/ai/writes/confirm` | `kind`: contact \| contract \| attachment \| work_order_from_contract \| … |
| POST | `/api/ai/writes/cancel` | 取消预览，不写业务表，记审计 |
| GET | `/api/ai/writes/audit` | 可读审计 |

## 与 S1

问进度/钱/工资仍走 `POST /api/ai/factory/ask` 只读，不进落单流水线。

## 验收清单

1. 名片 fixture → 联系人预览；确认后有联系人/附件；无新合同/加工单  
2. 订单 fixture → 合同预览；取消不写；确认后有单据+审计；同 preview 不双写  
3. 风景图 → 追问，不静默写库  
4. unknown → 追问，不写库  
5. 侧栏仍为 `.kgd-sidebar-primary`（工作台等）  
6. 单测：`apps/api/test/ai-s2-intake.test.ts`  
7. 冒烟：`scripts/ai-s2-smoke.mjs`  
8. 截图≥3：名片确认卡、订单确认卡、确认后合同列表
