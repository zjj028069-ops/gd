# 一句话生成新功能 · 样例 3 快递约件（2026-10-21）

> Allen：不开云端；现网 `/opt/sedric01` 热修。基线 **v1.0.29**。不重建库、不改密码、不改毛玻璃风格。  
> 合格句：`做一个快递约件：寄件人从客户带、货物从出库单带、填运单号回写出库，侧栏要有入口`

## 目标

聊天一句话 → 方案预览卡 → 确认后在 **MES 壳内**生成「快递约件」轻量应用：列表 + 表单 + 状态（待约/已寄/异常）+ 侧栏入口；约件可挂销售出库单；填运单号写回该出库单扩展值；停用藏入口、回退干净。**禁止**外挂独立站。无快递连接器时运单号手工填。

## 数据（增量迁移 120）

表 `ai_lite_records`（若不存在则建）：

- id, tenant_id, app_id → ai_ext_apps(id)
- status: 待约 | 已寄 | 异常
- sender_name, sender_customer_id（可空）
- stock_out_id, stock_out_code（挂 shipments / 销售出库）
- goods_summary, tracking_no
- payload jsonb 默认 {}
- created_by, created_at, updated_at

`ai_ext_apps` 复用：entity 用 `lite_app`（或保留 sale_stock_out 但 spec.kind=`lite_express`）；menu_label=`快递约件`；menu_path=`/ai/lite/{appId}`；spec 含 statuses、template=`express_pickup`。

确认创建时：若销售出库尚无「运单号」扩展字段，可顺带 insert 一条 entity_ext_fields(entity=sale_stock_out, name=运单号, field_type=快递单号或单行文本, options.sedric_app_id=appId) 供回写；回退时删该字段与 records。

## 解析

`parseExtUtterance` 或并列 `parseLiteUtterance`：命中 `快递约件|约快递|做.*快递约件|快递上门` 等 → op=create_lite, template=express_pickup, menu=true。  
聊天 `looksLikeS3` 同步放宽。

方案卡摘要须含：将生成壳内应用「快递约件」、状态机、侧栏入口、挂出库、运单回写、回退说法。

## API

- 现有 preview/confirm 扩展支持 lite
- `GET/POST /api/ai/lite-apps/:appId/records`
- `PATCH /api/ai/lite-apps/:appId/records/:id`（改状态、运单号）
- 写运单号时：更新 record.tracking_no，并把值写入挂接出库的 entity_ext_values（sale_stock_out + stock_out_id）；记审计
- 列表出库候选：复用 `GET /api/warehouse/shipments`；客户：现有客户列表 API

## UI

- 新页 `LiteExpressPage` 路由 `/ai/lite/:id`（round10/router + Shell 已注入 ext 菜单即可进）
- 列表：状态 chip 筛选；新建抽屉：选客户（寄件人）、选出库单（带出货物摘要）、状态默认待约
- 行内填运单号 → 保存并回写出库；状态可改 已寄/异常
- ExtApps 管理台可见该扩展；停用/回退走现有流程
