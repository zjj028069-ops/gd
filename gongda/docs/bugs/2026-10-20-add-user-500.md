# 2026-10-20 系统管理「新增用户」全局 500

## 现象
路径：系统管理 / 用户管理 / 用户添加。填写用户名「顾哥」、姓名「顾哥」、手机、密码后提交，右侧连续红色 toast「服务暂时无法处理请求」（API 全局 500：`服务暂时无法处理请求`）。

## 根因
- 接口：`POST /api/system/users`（`apps/api/src/system-admin.ts`）
- 原始异常（API 日志）：
  ```
  new row for relation "users" violates check constraint "users_username_check"
  code: 23514
  detail: Failing row contains (..., 顾哥, 顾哥, ...)
  ```
- 库约束（`001_foundation.sql`）：`username text NOT NULL UNIQUE CHECK (length(username) BETWEEN 3 AND 80)`
- 「顾哥」按字计仅 **2** 字，不满足 ≥3；`text(body.username)` 未做最小长度校验；错误码 `23514` 未在 `app.ts` 错误处理中映射，落入兜底 500 文案。
- 非席位配额问题（席位满应为 409「启用成员数量已达本企业席位配额」）。
- 对照：`platform.ts` 成员创建有 `minLength:3` + ascii pattern；系统管理路径此前未对齐最小长度。中文账号本身允许（「顾哥哥」3 字可成功）。

## 修复（v1.0.8）
1. `system-admin.ts`：账号 trim 后强制 ≥3；角色存在性校验；账号重复预查/捕获 → 409「账号已存在」；CHECK 兜底 → 422 中文提示。
2. `app.ts`：映射 `23514` / `users_username` 相关 `23505` 为明确中文 4xx。
3. `apps/web/src/kgd/pages/system/users.tsx`：用户名 min3/max80、密码 min6 前端校验。

## 验收
- 「顾哥」→ 422，不再 500
- 「顾哥测」→ 201，列表可见，可登录
- 重复账号 → 409
- 不重建库、不改密码、不碰 garment-*
