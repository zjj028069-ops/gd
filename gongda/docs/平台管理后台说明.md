# 平台管理后台（/platform）

给平台运营方用的后台：开通企业、给企业开管理员账号、设置服务期限与配额、停用企业。
界面沿用原系统外壳（侧栏、面包屑、列表、详情的样式完全一致）。

- 入口：`<系统地址>/platform`（与企业员工的登录入口完全分开）
- 账号：**独立的平台账号**，与任何企业账号无关；企业管理员的登录访问不了平台接口，平台登录也访问不了企业接口。

## 功能

| 位置 | 功能 |
|---|---|
| 企业管理 → 列表 | 按状态筛选（正常 / 30 天内到期 / 已到期 / 已停用，带数量）、按名称/标识/管理员查询、分页 |
| 新增 | 企业名称、企业标识（员工登录时填）、首个管理员账号和姓名、到期时间、账号数/商品数/附件存储上限；自动生成初始密码（只显示一次，可复制），并预置常用计量单位 |
| 企业详情 | 字段概况（状态、到期、用量/上限）；修改服务与配额；续期一年；停用/启用企业 |
| 详情 → 账号 | 列出账号；新增账号（生成初始密码）；改角色；重置密码（旧密码和已登录会话立刻失效）；停用/启用 |
| 详情 → 操作记录 / 平台操作日志 | 谁在什么时候对哪个企业做了什么 |

规则：
- **停用企业**：该企业所有人立刻下线、无法登录；数据保留，随时可启用。
- **到期 / 只读**：企业资料仍可查看，系统里已接入服务状态检查的写操作会被拦下（提示「企业服务已到期」）。
- **不能让企业失去最后一个管理员**：唯一的管理员不能被停用或改成别的角色（前后端都会拦）。
- **多企业共用的账号**不能在某一个企业里重置密码（避免影响其他企业）。
- 平台**不提供删除企业**，只能停用。
- **用户名只在企业内唯一**：不同企业可以有同名账号（如都叫「111」），它们是完全独立的账号，各自的密码只能登录自己的企业；同一企业内不能重名（迁移 `125_username_per_tenant.sql`，由数据库触发器保证）。

## 创建平台账号

第一个平台账号用命令行创建（会生成随机初始密码，只显示一次）。账号已存在时会重置它的密码并踢掉它的登录。

**本机开发**（PGlite 嵌入数据库同一时间只能被一个进程打开，所以先停服务）：

```
关闭 SEDRIC 命令行窗口（停止服务）
npm run platform:operator -w @gongdan/api -- platform.admin 平台管理员
双击 start-windows.cmd 重新启动
```

开发环境下密码同时写入 `.local/platform-credentials.txt`（不进 git）。

**服务器（现在是 PGlite）**：同理，先 `pm2 stop sedric-api`，在 `/opt/sedric01` 执行上面的命令（带上 start-api.sh 里的 `DB_MODE`、`LOCAL_DB_DIR` 环境变量），再 `pm2 start sedric-api`。

**以后换成 PostgreSQL 生产库**：命令要用执行数据库迁移的账号（表的所有者）连接数据库（`DATABASE_URL`），应用运行账号没有写平台账号表的权限——这是故意的。

## 安全设计

- 迁移 `124_platform_console.sql`：新增平台账号、平台会话、平台操作日志三张表，只给登录角色 `gd_auth` 最小权限（读账号、只改最后登录时间、会话增删、日志**只能追加**）；企业角色完全碰不到。
- **不新增数据库角色、不改任何企业表的行级隔离策略**，生产启动自检基线不变。
- 跨企业操作全部用系统已有的角色按企业逐个进行：读清单用 `gd_auth`，建企业/账号/改成员用 `gd_platform`（带企业上下文），改配额用 `gd_tenant`（进入该企业的隔离范围）；启停企业只通过受控函数 `platform_set_tenant_active` 改一列。
- 平台只读企业概况（人数、配额、用量），**不读取任何企业的业务数据**。
- 独立 httpOnly Cookie（生产为 `__Host-gd_platform`，SameSite=Strict）+ 独立 CSRF；登录限速（每分钟 10 次）；所有写操作记日志。
- 接口：`apps/api/src/platform-console.ts`；界面：`apps/web/src/modules/platform/`；命令：`apps/api/src/platform-operator.ts`。
